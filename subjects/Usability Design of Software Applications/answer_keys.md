i.   Match between system and the real world: The system
should speak the users' language using familiar concepts,
words, and phrases, following real-world conventions (e.g.,
using a shopping cart icon for e-commerce).
ii.   User control and freedom: Users should feel in control and
have a clearly marked "emergency exit" to leave an unwanted
state without extended dialogue (e.g., an easy undo/redo, or a
clear cancel button during checkout).
iii.   Recognition rather than recall: Minimize the user's memory
load by making objects, actions, and options visible. The user
shouldn't have to remember information from one part of the
dialogue to another (e.g., displaying previous search history).
iv.   Aesthetic and minimalist design: Dialogues should not
contain irrelevant or rarely needed information. Every extra
unit of information competes with the relevant units and
diminishes their relative visibility.
v.   Help and documentation: Even if the system can be used
without documentation, it should be available, easy to search,
focused on the user's tasks, and list concrete steps to be carried
out.

Ans:
Marks Distribution: Steps (6M), Example (4M)
Software redesign is an iterative process, typically following the
principles of User-Centered Design (UCD).
Steps to Redesign a Software Application:
1. Research & Analysis (Specify Context of Use): Identify the
current users, their pain points with the existing application, and
their key goals. Methods include user interviews and analyzing
current usage data (e.g., common drop-off points).
2. Specify Requirements: Define the detailed user needs and the
problems the redesign must solve, aligning them with business
objectives. These become the benchmarks for the new design.
3. Design Solutions (Prototyping): Create initial design concepts, [10]
sketch wireframes, and develop prototypes (low or high fidelity)
for the new interface and task flows. Focus on simplifying
interactions and improving information hierarchy.
4. Evaluate the Design (Usability Testing): Test the prototypes
with real users to gather feedback, identify usability problems,
and validate that the new design meets the defined requirements.
5. Iterate and Refine: Use the evaluation results to make necessary
changes and repeat the design and evaluation steps until the
usability goals are achieved.
Suitable Example: Redesigning a Public Library Website
• Problem: Users struggle to find the online book catalog and the
'Reserve a Book' button.
• Redesign Steps:
1. Research: Observe users at the library and find that they
assume the search bar only works for physical locations.
2. Requirements: The new system must allow users to
reserve a book in under three steps.
********** 4 **********

3. Design: Design a new homepage with a single, prominent
search bar clearly labeled "Search Books and Resources"
and a large, visible button for "My Loans/Reserves."
4. Evaluate: Test a prototype with five library visitors,
asking them to reserve a popular book. If they succeed
quickly, the design is validated.

Visibility of System Status: The system must always keep users
informed about what is going on through appropriate and timely
feedback. For example, when a smart light bulb receives a command to
turn on, the app should show a loading state before confirming the light
is on.
Consistency and Standards: Users should not have to wonder whether
different words, situations, or actions mean the same thing. All controls
that perform the same function (e.g., a "Save" button) should look and
behave the same way across the application.
Error Prevention: The best design is one that prevents problems
from occurring in the first place. This can be done by providing
constraints (e.g., disabling a button until all required fields are filled) or
by offering a confirmation before a critical action.
Flexibility and efficiency of use: The system should cater to both
inexperienced and experienced users. Experts should be able to use
accelerators or shortcuts (e.g., keyboard commands, customized settings)
to speed up their interaction.
Help users recognize, diagnose, and recover from errors: If an error
does occur, the message should be expressed in plain language, precisely
indicate the problem, and constructively suggest a solution. A
message like "Please check your network connection" is better than a
technical error code.
